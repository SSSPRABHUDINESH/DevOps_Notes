## SonarQube 

**SonarQube** is an open-source static code analysis platform used to measure, inspect, and track code quality and security. It acts as an automated "gatekeeper" in your CI/CD pipelines (like GitHub Actions) to catch bugs, code smells, and vulnerabilities early before code hits production.

---

### Core Concepts & Architecture

SonarQube analyzes source code across multiple languages using specific rule sets.

* **Static Application Security Testing (SAST):** Scans source code without executing it to detect security flaws and maintainability issues.
* **Quality Gates:** A set of Boolean conditions (e.g., *"Coverage must be > 80%"*, *"0 Critical Security Bugs"*) that a build must pass to be approved.
* **Clean as You Code:** SonarQube focuses primary metrics on **New Code** (code added or modified recently) to ensure new changes don't introduce debt.

**Key Metrics Tracked:**
* **Bugs:** Code that is demonstrably wrong or likely to cause a runtime crash.
* **Vulnerabilities:** Known security weaknesses open to exploitation.
* **Security Hotspots:** Security-sensitive code that requires manual developer review (e.g., hardcoded IP addresses or broad permissions).
* **Code Smells:** Maintainability issues that make code confusing or hard to refactor.
* **Technical Debt:** The estimated effort/time required to fix all code smells and issues.
* **Duplications & Coverage:** Percentage of duplicated code blocks and test code coverage.

### Integration: GitHub Actions + SonarQube Flow

In a standard DevOps flow, GitHub Actions triggers a build on a Pull Request (PR) or push, runs tests, and invokes the **SonarScanner** to send analysis metrics to the SonarQube server.

```
┌─────────────────┐       ┌──────────────────────┐       ┌─────────────────┐
│  Developer Push │ ────> │ GitHub Actions CI/CD │ ────> │ SonarQube Server│
└─────────────────┘       └──────────┬───────────┘       └─────────────────┘
                                     │                            │
                                     │ <── Checks Quality Gate ───┘
                                     ▼
                            [ Pass / Fail Pipeline ]

```

1. **Trigger:** Developer pushes code or opens a PR.
2. **Scan:** GitHub Actions runs `sonar-scanner` (or language-specific CLI).
3. **Analysis Processing:** Scanner sends AST/metrics to the central SonarQube instance.
4. **Quality Gate Evaluation:** SonarQube processes the scan and evaluates the Quality Gate status.
5. **Pipeline Decision:** If the Quality Gate **Fails**, the GitHub Action pipeline halts, blocking the PR merge.

### Key Configuration Files

#### 1. `sonar-project.properties` (Repository Root)

Defines project-level metadata and scan rules for the SonarScanner CLI.

```properties
# Unique project key and name in SonarQube
sonar.projectKey=my_app_backend
sonar.projectName=My App Backend

# Path to source code and exclusions
sonar.sources=src
sonar.exclusions=**/vendor/**,**/*.spec.ts

# Code Coverage Execution Reports
sonar.javascript.lcov.reportPaths=coverage/lcov.info

```

#### 2. `.github/workflows/sonarqube.yml` (GitHub Action Workflow)

Triggers the SonarQube scan during your CI pipeline.

```yaml
name: SonarQube Code Analysis

on:
  push:
    branches: [ "main", "develop" ]
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  sonarqube:
    name: SonarQube Scan
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Fetch all history for accurate blame/diff analysis

      - name: SonarQube Scan
        uses: SonarSource/sonarqube-scan-action@v2
        env:
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}

      - name: SonarQube Quality Gate Check
        uses: SonarSource/sonarqube-quality-gate-action@v1
        timeout-minutes: 5
        env:
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}

```

### Cheat Sheet: Key Terminology

| Term | What it Means | Impact on Pipeline |
| --- | --- | --- |
| **SonarScanner** | The CLI executable running inside GitHub Actions. | Parses code and uploads raw telemetry. |
| **Quality Gate** | The pass/fail criteria policy. | Fails the GitHub Action job if metrics fall below threshold. |
| **Quality Profile** | The set of active rules for a language (e.g., Java, JS). | Determines *what* issues are flagged during scanning. |
| **Webhook** | Communication bridge back to GitHub. | Notifies GitHub PRs with analysis status automatically. |
